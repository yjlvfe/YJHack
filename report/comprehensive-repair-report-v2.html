4 · السبب الجذري لـ«Not Responding» + الشاشة السوداء (مؤكَّد بالـbytecode)

كل شاشة في المود كانت تستدعي super.render() ⇐ Screen.render(). بتفكيك net.minecraft.client.gui.screen.Screen (Yarn) من كاش Loom:

Screen.render(DrawContext,int,int,float):
   6: invokevirtual  renderBackground(...)   // يُستدعى تلقائيًا كل frame

Screen.renderBackground(...):
  18: invokevirtual  applyBlur()             // Blur على كامل الشاشة (post-effect)
  23: invokevirtual  renderDarkening(...)     // تعتيم متدرّج

فطالما كانت شاشة المود مفتوحة، كان applyBlur()+renderDarkening() يعملان كل frame فوق العالم الحي. النتيجة:

  1. الشاشة السوداء / عدم رؤية اللاعبين — مُثبت. الإصلاح السابق خفّض شفافية طبقة المود فقط ولم يوقف Blur الأصلي.
  2. المرشّح الأول للتجمّد — applyBlur() تمريرة framebuffer كاملة؛ تفاعلها مع Iris/Sodium معروف بأنه سبب توقّف Render thread على بعض كروت الشاشة.

الملف/السطر المسؤول (جهة المود): ModGuiClient.BaseScreen.render() القديم الذي ينادي super.render(...) لكل شاشة دون تجاوز renderBackground.

الإصلاح

// YjScreen (الأساس الجديد)
@Override public void renderBackground(DrawContext ctx,int mx,int my,float d){
  /* فارغ عمدًا: لا super.renderBackground → لا applyBlur/renderDarkening.
     يُرسم فقط tint خفيف ~0x22 في render(). */
}
@Override public boolean shouldPause(){ return false; } // يبقى العالم يتحرك خلف اللوحة

تفاصيل: runtime-diagnosis.md.

5 · إصلاح AutoRight + سياسة Fire Charge

الخطأ: الفرع else القديم كان يشغّل حلقة CPS لأي عنصر ليس بلوكًا في اليد — فالفايربول يخرج بسرعة CPS. الحل: تصنيف مركزي في autoright/RightClickPolicy.java.

الفئةالعناصرالسلوك
SINGLE_PRESSFire Charge، Ender Pearl، Snowball، Egg، Splash/Lingering Potion، Wind Charge، XP Bottle، Ender Eye، Fishing Rod، Trident، Bow، Crossbow، Buckets، وكل UseAction من BOW/CROSSBOW/SPEAR/TOOT_HORNاستخدام واحد لكل ضغطة فعلية — لا CPS مطلقًا حتى مع إيقاف Block Mode
BLOCKأي BlockItemCPS burst فقط عند تفعيل Block Mode
PASS_THROUGHكل ما عدا ذلك (طعام، أدوات، درع…)يُترك إدخال Minecraft كما هو دون أي synthetic click

التصنيف بالـregistry id (مستقر عبر إصدارات Yarn) + UseAction. تدفّق الضغط: physical mouse → classify → single-press/repeat/pass-through → vanilla. المنطق: عند الحافة الصاعدة لا يفعل المود شيئًا (Minecraft يطلق استخدامًا واحدًا)، وأثناء الاستمرار يفرض setKeyPressed(RMB,false) لمنع تكرار Minecraft، والاستخدام التالي يحتاج RELEASE ثم PRESS.

نتائج اختبار 20 ضغطة (اختبار منطقي headless — نُفِّذ فعليًا)

[PASS] 20 separate presses = 20 uses   expected=20 actual=20
[PASS] hold 200 ticks = 1 use          expected=1  actual=1
[PASS] press/release/press = 2 uses    expected=2  actual=2
[PASS] 5 long holds = 5 uses           expected=5  actual=5
[PASS] no press = 0 uses               expected=0  actual=0
ALL PASS
هذا اختبار للعقد المنطقي (rising-edge) الذي يطبّقه handleSinglePress. التأكيد النهائي (فايربول حقيقي على سيرفر) يحتاج اللعبة — مدرَج ضمن اختبارات Lunar غير المُنفَّذة بعد. التفاصيل: right-click-policy.md.

6 · إعادة تصميم GUI

واجهة جديدة كليًا: بلا Blur (رؤية العالم واللاعبين)، Theme موحّد، عناصر مخصصة (Toggle switch، Slider مع صندوق إدخال رقمي متزامن، Keybind، Status chip)، Dashboard ببطاقات حيّة (اسم/وصف/حالة/مفتاح/قيم)، شريط سفلي ثابت (Back/Reset/Save)، رسالة «Settings saved»، Tooltips على المرور بدل مربعات «!»، تخطيط متجاوب يدعم 720×1280. حُذفت النصوص القديمة («READY» لكل شيء، «Locked modules…»).

الأداء: لا حفظ للكونفيق كل frame/حرف؛ التطبيق حي في الذاكرة والحفظ على debounce 350ms / إفلات المتزلج / Save / الإغلاق؛ لا حلقة أنيميشن منفصلة. مقارنة كاملة: gui-before-after.md.

معيار القبول البصري (يجب فحصه على Lunar): عند فتح الواجهة أمام لاعب قريب يجب أن تُرى حركته بوضوح خلف اللوحة. لا يمكن إعلان نجاحه من المراجعة الثابتة وحدها.

7 · الإعدادات (جسر typed بدل reflection)

سابقًا كان GUI ينسخ الحقول بالاسم عبر reflection بين كائني كونفيق مختلفين (يُسقط غير المتطابق بصمت — وكان سببًا في عدم تطبيق/عكس الإعدادات). الآن كل شاشة تحرّر كائن Config الخاص بالمود نفسه وتدفعه عبر:

Module.applyRuntimeConfig(cfg);  // تطبيق فوري في الذاكرة
Module.saveConfigStatic(cfg);    // كتابة الملف (typed)

أُضيف saveConfigStatic لـTracker وAimAssist (كان موجودًا في البقية). لا reflection. حقول CPS تُكتب الآن كـint (لا floats مثل 10.0) فيزول عدم تطابق الأنواع القديم.
